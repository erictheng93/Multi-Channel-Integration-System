# API 監控系統使用指南

## 概覽

API 監控系統是 Multi-Channel Customer Support System v3.0 的重要新功能，提供實時的 API 健康狀態監控和詳細診斷功能。

## 功能特色

### 🔄 實時監控
- **15 秒自動刷新**: 系統自動每 15 秒更新 API 狀態
- **手動刷新**: 支援立即手動更新狀態
- **實時狀態追蹤**: 即時監控所有 API 端點健康狀況

### 📊 智能分類
- **正常 (Healthy)**: 回應時間 < 1000ms，狀態碼 200
- **警告 (Warning)**: 回應時間 1000-3000ms，或非致命錯誤
- **錯誤 (Error)**: 回應時間 > 3000ms，或 API 無法訪問

### 📱 響應式設計
- **桌面優先**: 大螢幕下顯示詳細資訊
- **平板適配**: 中等螢幕自適應佈局
- **手機支援**: 小螢幕下優化的觸控體驗

## 使用方式

### 訪問監控頁面

1. 登入管理後台
2. 點擊左側導航的 "API 監控"
3. 系統會自動開始監控 API 狀態

### 查看詳細資訊

1. **統計概覽**: 頁面頂部顯示四個統計卡片
   - 總計 API 數量
   - 正常運作數量 (綠色)
   - 警告狀態數量 (黃色)
   - 錯誤狀態數量 (紅色)

2. **點擊查看詳情**: 點擊任意統計卡片查看具體 API 清單
   - 顯示具體的 API 端點
   - 回應時間資訊
   - 錯誤原因說明

### 手動刷新

- 點擊頁面右上角的 "手動刷新" 按鈕
- 或等待 15 秒自動刷新

## API 狀態說明

### 正常狀態 (綠色)
- **回應時間**: < 1000ms
- **狀態碼**: 200 OK
- **說明**: API 正常運作，效能良好

### 警告狀態 (黃色)
- **回應時間**: 1000-3000ms
- **狀態碼**: 200 但較慢，或輕微錯誤
- **說明**: API 可用但效能較慢，需要注意

### 錯誤狀態 (紅色)
- **回應時間**: > 3000ms 或無回應
- **狀態碼**: 404, 500, 或連接失敗
- **說明**: API 無法正常使用，需要立即處理

## 監控的 API 端點

### 核心系統 API
- `/api/system/health` - 系統健康檢查
- `/api/system/config` - 系統設定
- `/api/auth/login` - 用戶登入
- `/api/auth/refresh` - Token 刷新

### 業務功能 API
- `/api/conversations` - 對話管理
- `/api/conversations/:id/messages` - 訊息管理
- `/api/teams` - 團隊管理
- `/api/teams/:id/members` - 團隊成員
- `/api/customers` - 客戶管理

### 平台整合 API
- `/api/platforms/line/webhook` - LINE 整合
- `/api/platforms/facebook/webhook` - Facebook 整合
- `/api/qr-codes` - QR Code 管理

## 環境差異說明

### 開發環境特徵
- **本地資料庫**: 使用本地 D1 資料庫
- **快速回應**: 通常回應時間 < 500ms
- **高可用性**: 本地開發通常 100% 可用

### 生產環境特徵
- **網路延遲**: 可能有額外的網路延遲
- **負載影響**: 真實用戶負載可能影響效能
- **CDN 快取**: Cloudflare CDN 可能影響回應時間

## 故障排除

### 常見問題

1. **大量 API 顯示錯誤**
   - 檢查網路連接
   - 確認 Cloudflare Worker 是否正常運作
   - 查看 Cloudflare Dashboard 是否有服務異常

2. **回應時間過慢**
   - 檢查資料庫連接狀態
   - 確認是否有大量併發請求
   - 檢查 Cloudflare 服務區域設定

3. **部分 API 無法訪問**
   - 確認 API 端點路由設定
   - 檢查權限配置
   - 查看錯誤日志詳細資訊

### 診斷步驟

1. **檢查系統狀態**
   ```bash
   curl https://your-domain.com/api/system/health
   ```

2. **查看 Worker 日志**
   ```bash
   wrangler tail
   ```

3. **檢查資料庫狀態**
   ```bash
   wrangler d1 execute your-db --command="SELECT 1"
   ```

## 最佳實踐

### 監控建議
- 定期查看 API 監控頁面
- 關注警告狀態的 API，預防問題擴大
- 記錄錯誤模式，建立預警機制

### 效能優化
- 優化響應時間超過 1000ms 的 API
- 使用 KV 快取減少資料庫查詢
- 定期清理不必要的資料

### 安全考量
- 監控異常的 API 調用模式
- 注意來自異常來源的大量請求
- 定期檢查權限配置
