#  系統權限對照表 (Permission Matrix)

##  (Core Concept Overview)

本系統採用 **2-tier 角色權限系統**:
- **Admin (管理員)**: 系統最高權限,可管理所有資源
- **Agent (客服)**: 基本客服權限,受限制的資源訪問

```
權限層級架構:
┌─────────────────────────────────────┐
│  Admin (管理員) - Level 2 │
│ 完整系統控制權 │
│ 所有資源的 CRUD 操作 │
│ 團隊與成員管理 │
│ 系統設定與監控 │
└─────────────────────────────────────┘
                 ↓ 繼承
┌─────────────────────────────────────┐
│  Agent (客服) - Level 1 │
│ 查看所有對話 │
│ 僅能回覆指派的對話 │
│ 僅能發送指派對話的訊息 │
│ 僅能撤回自己的訊息 │
└─────────────────────────────────────┘
```

## / (Detailed Permission Breakdown)

###  角色權限定義

#### 1️ Admin (管理員)

**權限代碼**: `{ resource: '*', action: '*' }`

**完整權限列表**:

| 功能模組 | 權限範圍 | 說明 |
|---------|---------|------|
| **系統管理** |  完整控制 | 系統設定、監控、日誌查看 |
| **團隊管理** |  完整 CRUD | 創建、編輯、刪除團隊 |
| **成員管理** |  完整 CRUD | 新增、編輯、移除成員 |
| **對話管理** |  查看所有對話 | 包含已指派、未指派、所有團隊 |
| **對話操作** |  回覆任何對話 | 不受指派限制 |
| **訊息管理** |  發送任何訊息 | 不受指派限制 |
| **訊息撤回** |  撤回任何訊息 | 包含其他人的訊息 |
| **標籤管理** |  完整 CRUD | 創建、編輯、刪除標籤 |
| **客戶管理** |  查看所有客戶 | 不受團隊限制 |
| **報表功能** |  所有報表 | 系統、團隊、個人報表 |
| **QR碼管理** |  完整 CRUD | 生成、停用、查看統計 |
| **整合設定** |  LINE、Facebook | 平台串接管理 |

---

#### 2️ Agent (客服)

**權限代碼**:
```typescript
{
  { resource: 'conversation', action: 'view' },
  { resource: 'conversation', action: 'reply', conditions: { assigned: true } },
  { resource: 'message', action: 'send', conditions: { assigned: true } },
  { resource: 'message', action: 'recall', conditions: { own: true } },
  { resource: 'tag', action: 'add', conditions: { teamScope: true } }
}
```

**權限列表**:

| 功能模組 | 權限範圍 | 限制條件 | 說明 |
|---------|---------|---------|------|
| **系統管理** |  無權限 | - | 無法訪問系統設定 |
| **團隊管理** |  無權限 | - | 無法創建、編輯團隊 |
| **成員管理** |  無權限 | - | 無法新增、編輯成員 |
| **對話管理** |  查看所有對話 | 包含搶單池 | 可看到未指派的對話 |
| **對話操作** |  有限回覆 | 僅指派給自己 | 無法回覆未指派對話 |
| **訊息管理** |  有限發送 | 僅指派的對話 | 只能在指派對話中發送 |
| **訊息撤回** |  僅自己 | `own: true` | 只能撤回自己發送的訊息 |
| **標籤管理** |  僅添加 | 團隊範圍 | 可添加標籤但不能刪除 |
| **客戶管理** |  查看客戶 | 有團隊則限團隊 | 可查看相關客戶資料 |
| **報表功能** |  個人報表 | - | 僅能查看自己的報表 |
| **QR碼管理** |  查看/使用 | 團隊範圍 | 可使用團隊QR碼 |
| **整合設定** |  無權限 | - | 無法設定平台串接 |

##  (Permission Check Logic)

### 權限檢查流程

```
使用者請求 API
       ↓
┌─────────────────┐
│  JWT 認證 │ → jwtAuth 中間件
│  驗證 Token │
└────────┬────────┘
         ↓
┌─────────────────┐
│  取得用戶資訊 │ → c.get('user')
│  - userId │
│  - role │
│  - teamId │
└────────┬────────┘
         ↓
    [Admin?]
    Yes No
 通過 ↓
         ┌─────────────────┐
         │  檢查具體權限 │ → PermissionService.checkPermission()
         │  - resource │
         │  - action │
         │  - conditions │
         └────────┬────────┘
                  ↓
            [有權限?]
            Yes No
          通過 403 Forbidden
```

### 條件限制邏輯

```typescript
// 1. assigned: 只能操作指派給自己的對話
if (conditions.assigned) {
  // 檢查對話的 assignedUserId 是否等於當前用戶 ID
  // 或者對話未指派 (搶單池)
}

// 2. own: 只能操作自己的資源
if (conditions.own) {
  // 檢查資源的 ownerId 是否等於當前用戶 ID
}

// 3. teamScope: 只能操作團隊範圍內的資源
if (conditions.teamScope) {
  // 檢查資源的 teamId 是否等於當前用戶的 teamId
}

// 4. ownTeam: 只能管理自己的團隊
if (conditions.ownTeam) {
  // 檢查操作的 teamId 是否等於當前用戶的 teamId
}
```

## (Comparison: Admin vs Agent)

### 功能對比總表

| 功能類別 | Admin | Agent | 關鍵差異 |
|---------|-------|-------|---------|
| **對話可見性** | 所有對話 | 搶單池 + 指派 + 團隊 | Admin 100% 可見 |
| **對話回覆** | 無限制 | 僅指派的對話 | Agent 需先搶單 |
| **訊息發送** | 無限制 | 僅指派的對話 | Agent 受指派限制 |
| **訊息撤回** | 任何訊息 | 僅自己的訊息 | Admin 可撤回他人 |
| **團隊管理** | 完整 CRUD | 無權限 | Agent 完全無法操作 |
| **成員管理** | 完整 CRUD | 無權限 | Agent 完全無法操作 |
| **角色變更** | 可變更任何人 | 無權限 | 僅 Admin 可變更 |
| **密碼重設** | 可重設任何人 | 無權限 | 僅 Admin 可重設 |
| **標籤管理** | 完整 CRUD | 僅可添加 | Agent 不能刪除標籤 |
| **系統設定** | 完整訪問 | 無權限 | Agent 看不到系統頁面 |
| **報表功能** | 所有報表 | 個人報表 | Agent 僅看自己數據 |

### 操作限制範例

```
┌──────────────────────────────────────────────────┐
│  操作: 回覆客戶訊息 │
├──────────────────────────────────────────────────┤
│  對話狀態: 未指派 (搶單池) │
│ │
│  Admin: │
│ 可直接回覆 │
│ 不需要搶單 │
│ 回覆後不會自動指派 │
│ │
│  Agent: │
│ 無法直接回覆 │
│ 需要先「搶單」指派給自己 │
│ 指派後即可回覆 │

┌──────────────────────────────────────────────────┐
│  操作: 撤回訊息 │
├──────────────────────────────────────────────────┤
│  訊息發送者: Agent B │
│ │
│  Admin: │
│ 可以撤回 │
│ 即使是其他人發送的 │
│ 適用於管理不當內容 │
│ │
│  Agent A: │
│ 無法撤回 │
│ 只能撤回自己發送的訊息 │
│ 無法撤回 Agent B 的訊息 │
└──────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────┐
│  操作: 新增團隊成員 │
├──────────────────────────────────────────────────┤
│  Admin: │
│ 開啟「團隊管理」頁面 │
│ 點擊「新增成員」 │
│ 填寫表單並提交 │
│ 成功新增成員 │
│ │
│  Agent: │
│ 看不到「團隊管理」頁面 │
│ 無「新增成員」按鈕 │
│ 403 Forbidden (嘗試直接訪問 API) │
└──────────────────────────────────────────────────┘
```

##  實作細節

### 權限服務位置
- **Permission Service**: `src/services/permission-service.ts`
- **Auth Middleware**: `src/middleware/auth.ts`
- **Team Auth**: `src/modules/teams/middleware/team-auth.ts`

### 中間件使用
```typescript
// 1. 基本認證 (所有認證用戶)
app.get('/api/messages', jwtAuth, handler)

// 2. 僅管理員
app.post('/api/teams', jwtAuth, requireAdmin(), handler)

// 3. 管理員或團隊負責人 (已簡化為 requireAdmin)
app.put('/api/teams/:id', jwtAuth, requireManagerOrAdmin(), handler)

// 4. 團隊成員訪問
app.get('/api/teams/:id', jwtAuth, requireTeamAccess('id'), handler)

// 5. 角色層級檢查
app.post('/api/members', jwtAuth, requireRoleLevel('admin'), handler)
```

##  總結

### Admin (管理員) 能做什麼?
 **一切操作** - 無任何限制
 查看、編輯、刪除所有資源
 管理團隊與成員
 設定系統與整合
 查看所有報表與統計

### Agent (客服) 能做什麼?
 查看部分對話 (搶單池 + 指派 + 團隊)
 回覆指派給自己的對話
 發送訊息 (限指派的對話)
 撤回自己的訊息
 添加標籤 (團隊範圍)
 查看個人報表
 使用團隊QR碼

### Agent (客服) 不能做什麼?
 回覆未指派的對話 (需先搶單)
 撤回他人的訊息
 管理團隊
 管理成員
 變更角色
 重設密碼
 刪除標籤
 系統設定
 查看他人報表
