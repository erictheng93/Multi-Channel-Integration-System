# 文檔重組指南

## 概述

本指南說明了最近對專案文檔結構的重組，以改善導航和可維護性。

## 變更內容

### 之前（舊結構）
文檔之前分散在根目錄中，語言混合（中文和英文），分類不清楚：

```
docs/
├── README.md (中文)
├── SETUP_GUIDE.md
├── DEPLOYMENT_GUIDE.md
├── SCHEMA.md
├── CURRENT_STATUS.md
├── CHANGE_LOG.md
├── 其他各種文件...
```

### 之後（新結構）
文檔現在按邏輯類別組織，命名一致：

```
docs/
├── README.md (主要索引)
├── api/                    # API 文檔
├── architecture/           # 系統架構文檔
├── enterprise/             # 企業功能
├── features/               # 功能文檔
├── guides/                 # 設置和部署指南
├── implementation/         # 實作詳情
└── testing/                # 測試文檔
```

## 主要改進

### 1. 邏輯分類
- **API 文檔** (`docs/api/`): 所有 API 相關文檔
- **架構** (`docs/architecture/`): 系統設計和架構
- **企業功能** (`docs/enterprise/`): 進階企業功能
- **功能** (`docs/features/`): 個別功能文檔
- **指南** (`docs/guides/`): 逐步設置和部署指南
- **實作** (`docs/implementation/`): 技術實作詳情
- **測試** (`docs/testing/`): 測試策略和報告

### 2. 一致的語言
- 所有文檔現在都使用中文以提高可讀性
- 所有文件的命名慣例一致
- 清楚、描述性的文件名稱

### 3. 改善的導航
- 主要 `README.md` 作為綜合索引
- 每個類別都有清楚的描述
- 相關文檔之間的交叉引用
- 基於用戶角色的導航（新用戶、開發者、DevOps）

## 遷移指南

### 對於開發者
如果您有舊文檔路徑的書籤或引用，以下是對應關係：

| 舊路徑 | 新路徑 |
|--------|--------|
| `docs/README.md` (中文) | `docs/README.md` (主要索引) |
| `docs/SETUP_GUIDE.md` | `docs/guides/DEPLOYMENT_GUIDE.md` |
| `docs/API_PROXY_SETUP.md` | `docs/guides/API_PROXY_SETUP.md` |
| `docs/TESTING_GUIDE.md` | `docs/testing/` (多個文件) |
| `docs/ENTERPRISE_*.md` | `docs/enterprise/` |
| 各種實作文檔 | `docs/implementation/` |

### 對於新用戶
1. 從主要 [README.md](../README.md) 開始
2. 遵循「如何使用本文檔」部分
3. 根據您的角色選擇路徑：
   - **新用戶**: 快速開始 → 用戶手冊 → 部署指南
   - **開發者**: MVP README → 實作文檔 → 測試文檔
   - **DevOps**: Terraform 快速開始 → 部署指南 → 系統報告

## 新結構的優勢

### 1. 更好的可發現性
- 用戶可以快速找到相關文檔
- 清楚的分類減少搜尋時間
- 基於角色的導航路徑

### 2. 改善的可維護性
- 更容易更新和維護文檔
- 所有文檔的結構一致
- 清楚的所有權和責任

### 3. 增強的用戶體驗
- 資訊的漸進式揭露
- 情境感知的文檔
- 減少認知負荷

### 4. 更好的協作
- 清楚的貢獻指南
- 標準化的文檔格式
- 更容易的審查流程

## 文檔最佳實踐

### 1. 文件命名
- 使用描述性的 kebab-case 名稱
- 在相關時在名稱中包含文檔類型
- 對相關文檔使用一致的前綴

### 2. 內容結構
- 以清楚的概述開始
- 使用一致的標題結構
- 包含實際範例
- 提供相關文檔的交叉引用

### 3. 維護
- 隨代碼變更更新文檔
- 定期檢查和更新過時資訊
- 保持主要索引的最新狀態

### 4. 以用戶為中心的方法
- 為您的受眾寫作
- 提供多個入口點
- 包含故障排除資訊
- 使用清楚、簡潔的語言

## 未來改進

### 計劃的增強功能
1. **互動式文檔**: 添加互動式範例和教學
2. **API 文檔**: 從代碼自動生成 API 文檔
3. **影片指南**: 複雜設置程序的螢幕錄製
4. **多語言支援**: 逐步添加其他語言
5. **搜尋功能**: 跨所有文檔的全文搜尋

### 貢獻文檔
1. 遵循既定的結構
2. 為新文檔使用適當的類別
3. 添加新文檔時更新主要 README.md 索引
4. 遵循樣式指南和命名慣例
5. 包含相關文檔的交叉引用

## 回饋和支援

如果您對新的文檔結構有疑問或需要幫助找到特定資訊：

1. 首先檢查主要 [README.md](../README.md) 索引
2. 使用基於角色的導航指南
3. 在文件名稱和內容中搜尋關鍵字
4. 如果文檔缺失或不清楚，請提交問題
